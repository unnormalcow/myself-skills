# 字段命名、分类和核对规则

## 英文标准名与词根

- 优先沿用模板已有的英文名称、组织词汇表和用户确认的词根；缺少时先按中文业务含义构建可复用的中英词根表，再用词根组合字段名。
- 同一中文概念在实体名、字段名及不同表中使用同一个英文词根；相同字段含义不能因表不同而任意换词。
- 命名保持可读、可组合、无空格和标点（遵循模板既有大小写/分隔符格式）；不要把数据库物理字段名直接当作业务标准名，也不要为不明确的缩写猜全称。
- 实体英文名、实体描述、属性中文名、属性英文名、属性描述应分别落入映射页对应的 I-N 列。保留用户已有的非空字段；只补空白项。
- 对无法由字典或上下文确定的含义，不创建强行翻译的词根；保持空白并列入待核对项。

## 属性类型判断

按字段业务语义优先，其次参考数据库类型。输出值必须严格使用表中十个标准类别之一：

| 属性类型 | 识别依据 |
| --- | --- |
| 编码类 | 业务对象的唯一编码、单据编号、标识符等，用于标识实体或记录 |
| 代码类 | 有限枚举值或业务代码，如类型、来源、状态代码；不要把所有整数都归为代码 |
| 标志类 | 是否、启用/禁用、标志位等真假含义；`bit` 通常属于此类 |
| 文本类 | 名称、描述、备注及其他字符内容；字符型字典字段通常属于此类 |
| 金额类 | 金额、税额、成本、单价、费用等货币含义字段；字段名中出现“数量”等非货币语义时应复核 |
| 数值类 | 数量、计数、顺序号、非货币的整数或小数值 |
| 比率类 | 税率、汇率、折扣率、比例等比率含义字段 |
| 日期类 | 仅表示日期、期间或账期的字段；字典提供 date 类型时通常归入此类 |
| 时间类 | 仅表示时刻或时间段且不包含日期的字段 |
| 日期时间类 | 同时表达日期与时刻的字段；datetime 等类型通常归入此类 |

SQL 类型只能辅助判断，不能独立决定有业务语义的字段类别。例如，字符型的“客户编码”仍是编码类；数值型的“税率”仍是比率类；数值型的数量不能因字段名含“余额”就归为金额类。SQL Server `timestamp/rowversion` 不表示日期时间，需根据字段含义判定，无法确认时留空待核对。

## 精确匹配与长度

- 使用 `(物理表名, 物理字段名)` 作为字典匹配键，统一首尾空格和大小写；不要单独按字段中文名匹配。
- 同一物理表字段在字典中重复且定义一致时可复用；定义冲突时不要任选其一。
- 字典“长度”原样回填。不要用显示宽度、SQL 类型默认长度或其他字段长度替代。
- 如果字段确实没有长度值，保持长度空白并在待核对清单中注明，不写 `0`、`N/A` 或估算值。

## 最终一致性检查

- 映射页所有业务数据行的“来源类型”均为空，表头保持原样。
- 管理页每个已填字段的“属性类型”属于允许集合；“长度”与其对应字典记录完全相同。
- I-N 的补全结果能正确对应到管理模板；同名字段通过业务对象、表、来源信息和顺序消歧。
- 排除字段没有误入业务目录；其他用户已有内容、公式、样式和工作表结构未被意外覆盖。
- 记录精确匹配数、未匹配数、歧义数、排除数、类型分类数和长度缺失数，向用户简要汇报。
