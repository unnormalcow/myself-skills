# 数据资产目录建设调研助手 (Data Asset Catalog Survey)

> **Goal**: 帮助交付团队在「数据资产目录建设 / 数据治理」类项目中，系统化地完成**业务域调研**这一基础环节——从问卷设计、调研执行、结果分析，到产出数据资产清单、主数据梳理、数据标准建议与现状评估报告。

## 适用项目场景

本 skill 服务于「摸清数据家底、建立数据标准、提升数据治理水平」类项目，典型包括：
- 销售 / 采购 / 生产 / 财务 / 人力等部门级**数据资产目录建设**
- 业财一体化、Order-to-Cash（接单到回款）全链路数据梳理
- 主数据管理（MDM）现状评估与规范制定
- 数据治理规划前期调研、数据资产盘点

## When to Use

当用户出现以下任意意图时触发：
- "帮我设计一份【某业务域】数据资产目录建设调研问卷"
- "我们要做数据资产盘点 / 数据治理，先调研一下现状"
- "分析这份调研问卷的回收结果 / 访谈记录"
- "产出数据资产清单 / 主数据梳理 / 数据标准建议"
- "生成数据资产管理现状评估报告 / 调研报告"

## When NOT to Use

- 纯技术的数据中台/数据仓库实施（无业务域调研环节）— 引导至对应研发/架构流程
- 仅做 BI 报表开发、不涉及数据资产盘点
- 合同、法务、合规专项（提醒用户找对应负责人）

## 调研方法论（八维框架）

任何业务域的数据资产目录调研，都应覆盖以下 **8 个维度**（源自销售域调研问卷，可横向复用到其他域）：

| # | 维度 | 调研目标 | 典型问题方向 |
|---|------|----------|--------------|
| 1 | **业务概况** | 组织架构、业务范围、信息系统使用现状 | 组织按什么维度分组？用哪些系统？哪些环节还靠手工/纸质？ |
| 2 | **核心对象管理**（客户/供应商/物料等） | 主数据管理与全生命周期数据流转 | 有多少个活跃对象？主数据包含哪些属性？在哪个系统维护？ |
| 3 | **业务订单与执行流程** | 核心业务单据从创建到完成的全链路数据 | 单据如何创建？执行如何传递跟踪？变更有无版本追溯？ |
| 4 | **定价与结算/开票** | 价格策略、折扣、开票结算的数据管理 | 价格在哪维护？不同规则如何管理？开票依据是什么？ |
| 5 | **数据与报表** | 统计分析现状与数据可用性 | 需要哪些报表？能否从系统直接获取？数据准不准、全不全？ |
| 6 | **数据标准化与主数据** | 核心数据清单、编码规则、管理规范 | 各类数据在哪管理？编码是否统一？有无正式规范？ |
| 7 | **数据安全管理** | 访问控制与敏感数据保护 | 权限如何划分？敏感数据是否保护？关键操作有无审计日志？ |
| 8 | **使用痛点与优化需求** | 一线真实反馈与改进期望 | 最痛的 3 个问题是什么？最希望实现的一项改进？整体评分？ |

> 业务域替换示例：
> - 销售域 → 核心对象=客户，流程=合同→订单→发货→开票→收款
> - 采购域 → 核心对象=供应商，流程=请购→订单→收货→发票→付款
> - 生产域 → 核心对象=物料/BOM，流程=工单→投料→报工→入库
> - 财务域 → 核心对象=科目/核算项，流程=凭证→记账→报表→合并

## 核心数据资产分类（盘点清单骨架）

调研中需逐项盘点的数据类别（销售域示例，可映射到各域）：

1. **客户/对象主数据**：编码、名称、地址、联系人、付款条件、信用额度
2. **合同数据**：合同号、对象、产品、数量、金额、条款、有效期
3. **订单数据**：订单号、对象、物料、数量、价格、交期、状态
4. **发货/交货数据**：交货单、物料、数量、批次、装运点、发货日期
5. **发票/开票数据**：发票号、对象、金额、税码、收款状态
6. **应收/应付数据**：余额、账龄、未清项、回款/付款记录
7. **价格数据**：各对象各产品的价格、折扣规则
8. **信用额度数据**：额度、已用、可用、超限审批记录

> 每个数据类别在清单中需记录：**管理位置（系统/文件）、准确性与完整性、是否有正式管理规范**。

## 标准工作流

### 步骤 1：明确调研范围与对象
- 确认业务域、覆盖的产品线/市场维度、涉及的关联系统
- 确认调研对象岗位（如销售域：总监/主管/跟单/内勤/外贸）
- 输出《调研范围说明》（参考 references/research-report-template.md）

### 步骤 2：生成调研问卷
- 基于八维框架 + 业务域映射，生成定制化问卷
- 末附「受访者信息」与「一句话总结」便于分岗分析
- **Word 文档排版必须严格遵循 references/format-spec.md（公文格式标准）**：仿宋正文、黑体标题、楷体副标题与说明、题目加粗、正文首行缩进 2 字符、手工目录层级、Light Grid Accent 1 表格；分页符仅在大章节（一~五）前与封面/目录之间共 6 处，子章节（4.1~4.8）不加分页。该标准是客户范本的强制规范，不得用宋体/无样式/无缩进/无分页替代。
- 输出《XX 业务域数据资产目录建设调研问卷》（参考 references/survey-framework.md）

### 步骤 3：执行调研（问卷/访谈/工作坊）
- 指导用户如何开展：问卷发放 + 关键岗位深度访谈 + 系统走查
- 访谈聚焦：流程断点、数据盲区、手工环节、主数据一致性
- 参考 references/interview-guide.md

### 步骤 4：分析结果，产出数据资产清单
- 汇总问卷与访谈，识别数据资产、痛点、风险
- 产出《数据资产清单》《主数据梳理》《数据标准建议》
- 模板见 references/data-asset-inventory-template.md

### 步骤 5：生成现状评估报告
- 形成《数据资产管理现状评估报告》：家底盘点、链路打通情况、标准规范现状、安全风险、改进路线图建议
- 模板见 references/research-report-template.md

### 步骤 6：交付物归档与事项化（结合项目交付协同角色）
- 提醒用户将调研问卷、访谈记录、数据资产清单、评估报告上传**项目资料库**
- 提醒用户将识别出的**风险、待确认问题、遗留问题**创建为**事项**并分配负责人
- 区分**内部版**（含风险判断、成本、人员）与**客户可见版**材料

## 输出物清单（每次调研应至少产出）

- [ ] 调研范围说明
- [ ] 定制化调研问卷（八维框架）
- [ ] 访谈纪要 / 问卷回收汇总
- [ ] 数据资产清单（含管理位置、准确性、规范情况）
- [ ] 主数据梳理与编码规则现状
- [ ] 数据标准与规范建议
- [ ] 数据安全与权限现状
- [ ] 痛点 Top3 与改进需求
- [ ] 数据资产管理现状评估报告（含改进路线图建议）

## 注意事项（交付协同）

- **区分内部与客户可见信息**：对外输出前检查是否含成本、人员安排、未确认承诺、内部风险判断。
- **不替团队承诺**未经确认的交付范围、排期或价格；涉及合同/法务/合规问题，提醒用户找对应负责人。
- **所有结论基于调研证据**：标注"客户明确需求 / 内部判断 / 待验证信息"，避免把访谈主观表述当作既定事实。
- **主数据一致性**是高频风险点（同一对象多编码、信息不一致），需在清单与报告中重点标注。
