# 3DCity — 城市3D卡通微缩景观五视图

## 目标与优先级

为用户提供**能够辅助3D建模**的城市地标微缩景观参考图，而非复杂写实沙盘。优先级按顺序为：

1. **可建模**：轮廓清晰、结构简化、模块化、无过密细节。
2. **同一模型**：五个视角必须对应同一个物体集合、布局、尺寸关系与色彩。
3. **地标辨识**：用1–3个代表性城市地标表现城市特色。
4. **清晰观感**：简洁3D卡通、低多边形/玩具模型感、柔和打光。
5. **装饰效果**：不以繁复人物、车辆、霓虹灯和街道家具牺牲前四项。

不要把“卡通”理解为复杂、可爱但难以建模的主题公园沙盘；在用户说“更简单”“用于3D建模”时，应该进一步减法。

## 触发与输入

用户提供城市名称即可开始，不必反复追问。地标、风格、视角、尺寸、用途等均可选；有明确要求则优先执行。

默认设置：

| 项目 | 默认值 |
|---|---|
| 城市 | 取用户指定城市 |
| 地标 | 1个主地标 + 1个辅地标或代表性建筑群 |
| 风格 | **简洁3D卡通、low-poly、积木/树脂手办感** |
| 细节 | **低复杂度**，面向后续3D建模 |
| 视角 | 正视、后视、左视、右视、俯视，共5张 |
| 画幅 | **每张独立16:9**（非拼页、非九宫格） |
| 质量 | high，轮廓清晰，字体如有则锐化、无错别字 |
| 相机 | 正交投影（orthographic），视图间固定尺度 |
| 背景 | 纯净浅灰/暖白色摄影棚，无城市天际线杂景 |
| 材质 | 哑光塑料/陶土/低多边形，少量简单玻璃/水面 |
| 光照 | 统一柔和日光；默认**不制作复杂夜景光效** |
| 底座 | 简单完整的长方形底座、适度圆角、厚度一致 |
| 文字 | 默认不在模型上生成细小文字；确需城市名可仅在底座正面添加短名称 |

如果用户只要一张示意图，可优先提供3/4轴测展示图；如果用户明确要五视图，严格输出上述5个独立视角，不用轴测图替代。

## 必须遵循的制作流程

### 第一步：识别地标，做场景减法

- 提取1个最有辨识度的主地标、至多2个次要地标；如城市真实地标不确定，需要先查证地标造型与基本布局，不随意杜撰“真实复刻”。
- 每个地标只保留大体量形状、外轮廓、主体结构和少量标志性颜色。
- 组景默认：主地标1个、建筑2–3栋（可合并为一组）、桥1座（必要时附属结构1座）、树6–10棵、交通工具0–1个、广场或水景0–1处。
- 尽量剔除人群、路灯、栏杆雕花、繁杂立面、密集窗格、夜景灯带、花坛小品等；用户要求再逐项加回。

### 第二步：先固定唯一的3D空间布局

先在脑中或结构化描述中确定唯一的场景蓝图（scene blueprint），然后才生成所有视图。严禁每一张图重新设计场景。

坐标系：底座**正面**为 y 负方向，**后面**为 y 正方向；面向正视图时 x 从左到右，z 向上。

记录：底座宽/深/厚；每个地标的ID、中心点、包围盒尺寸、朝向、颜色；街道与水面走向；建筑数量；树与桥的位置。固定一个 front-marker（正面铭牌）仅用于认定朝向。

参见 `references/scene-blueprint.md`，范例 `examples/tianjin.json`。

### 第三步：生成“母版”，统一后续图像

- 优先用一个简明的场景布局说明 + 可视化母版锁定五视图一致性。
- 如使用图像编辑/图生图工具，以第一张通过审核的母版作后续视角参考；提示词每次强制包含“同一个模型，不能改变布局和物体数量”。
- 如果用户明确只要五张，母版是内部中间步骤，不应代替五张交付。不能因母版好看就停止。
- 始终要求**一个生成结果只包含一个视角**；不画五宫格、不拼画板、不附缩略图。

### 第四步：输出严格的五视图

按正视 → 后视 → 左视 → 右视 → 俯视依次生成，逐个审查。

| 视角 | 相机方向 | 必须成立的几何关系 |
|---|---|---|
| 正视 | 从 y− 看向 y+ | 底座正面铭牌可见；模型主立面与轮廓清楚 |
| 后视 | 从 y+ 看向 y− | 相对正视，左右位置反转；不得仍正对正面铭牌 |
| 左视 | 从 x− 看向 x+ | 展示底座深度；对面向正面的大转轮，应见轮体近似“薄边” |
| 右视 | 从 x+ 看向 x− | 与左视方向相反，物体前后顺序正确；同一轮体近似“薄边” |
| 俯视 | 从 z+ 向 z− | 真正垂直向下；屋顶、道路、地块、水面位置对应底图 |

**重要反例**：如果摩天轮平面与底座正面平行，那么正/后视可以看到大圆，左/右视应接近狭长薄轮廓，俯视亦应接近狭长轮边/结构投影。不能五个方向都看到一个完整正圆摩天轮，也不能把3/4角度误标为左视、右视或俯视。

所有视图都应显示整个模型/底座，留适当安全边距，保持相同高度关系和标志物集合；不要在一个视角凭空多出或减少建筑、树、桥或小船。

### 第五步：审核与修正

逐张执行 `references/quality-checklist.md`：

- 物体数量、位置和左右/前后关系是否一致？
- 正/侧/俯视方向是否真正确？
- 造型是否适合建模，去除细碎结构了吗？
- 有无背景城市、路人、文字伪影或多余装饰？
- 是否五张独立图像，全部16:9且高清？

出现错误只重做有问题的视角，引用已确认蓝图，不随意更改其他视角。

## 可建模几何约束

- 几何体用圆环、立方体、圆柱、圆锥、规则拱桥、低多边形树冠、简单屋顶等基础形体。
- 建筑立面每栋只保留2–4组门窗特征，装饰花纹通过材质或贴图表达，避免复杂浮雕。
- 摩天轮可简化为**1个外环 + 8–16条辐条 + 8–16个规则轿厢 + 1组支架**，通常采用12或16个轿厢；不应追求照片级钢索密度。
- 尽量用厚实可辨认的构件；避免易破损的超细悬空零件、彼此难以拆分的杂物。
- 河流默认一条平整蓝色面；桥可只有一座；仅当城市辨识度需要时加入船只、喷泉或地标碑石。
- 若用户提到3D打印、STL、可切片，启用**打印友好模式**：放大细杆与连接处、让底座与建筑有效接触、减少悬挑/悬空、减少独立小零件。不要承诺仅靠图片生成的模型已具备水密性或可打印性。
- 以上是**效果图和建模参考的视觉约束**；若用户需要真实可编辑3D几何文件，应另外建模、检验拓扑与比例，不可把PNG冒充3D模型。

## 生成工具与输出

- 当图像生成功能可用时，实际使用图像工具生成，而不是只给出提示词。每张都生成单视图、独立图像。
- 使用 `references/prompt-templates.md` 的通用场景约束和五个相机提示词；先填入城市、地标、scene blueprint，再启动生成。
- 如工具不能强制正交或保持真实三维一致性，应诚实提示“这些是AI视觉参考图，并非从同一三维网格精确渲染的CAD正交图”。
- 如用户要求精确建模用五视图且有3D渲染引擎可用，应**优先先建立简模，再从同一模型设置5个正交相机渲染**，而不是独立文生图碰运气。
- 输出文件建议命名：`<城市>_3DCity_01_front.png`、`02_back.png`、`03_left.png`、`04_right.png`、`05_top.png`。
- 可以提供ZIP汇总，但不能只交付一张拼版图；如用户愿意，还可附加一张独立轴测展示图（不计入五视图）。

## 迭代响应词

| 用户反馈 | 直接调整方式 |
|---|---|
| “太复杂 / 继续简化” | 建筑减到1–2栋、树减到4–6棵、摩天轮轿厢减至8–12个、移除船/喷泉/路灯/牌匾细节 |
| “更卡通” | 增大简单轮廓特征，降低纹理和真实感，使用圆润/low-poly体块 |
| “像积木 / 更适合打印” | 使用离散基础几何体、厚连接、压低悬挑、减少组件 |
| “五视图不一致” | 回到唯一蓝图，严格相机方位；优先同一3D模型正交渲染 |
| “图片不要拼图” | 每个视角单独调用/单独导出，禁止网格、拼页和合集画板 |
| “16:9、高清、锐化” | 每个视角16:9并保留余量；提升图像细节，确保短文字清晰 |

## 天津案例的固化经验

天津版保留“天津之眼 + 海河 + 意式风情街”。更利于建模的简化方案是：

- 大型天津之眼：1个圆环与简化支撑，12个吊舱；
- 中间海河：1条直线水面；前部仅1座桥；
- 右侧意式风情街：2栋浅色墙、红瓦屋顶的卡通建筑，1个醒目钟楼/塔楼轮廓（可和建筑合并）；
- 左侧海河标志：一块简洁大石块，可选；
- 树木6–8棵，船只最多1条；
- 去除人物、车辆、密集城市背景和复杂灯光。

范例布局在 `examples/tianjin.json`；该布局只是**创意景观拼贴**，不宣称天津之眼与意式风情街在现实中紧挨彼此。
