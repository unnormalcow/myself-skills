# HD-Operational-Report · 数据与口径参考

本文件是《区域经营分析报告》生成流程的数据字典与踩坑清单，供生成报告前核对、生成后自检。

---

## 一、必须提供的输入文件

| 文件 | 含义 | 关键结构 |
|---|---|---|
| `1010_部门业绩总览表.xlsx` | 部门（华北区）经营总表 | 6 个 sheet：预算 / 关键指标 / 总表 / 现金流量表 / 展开 / 业绩绩效表 |
| `2010_项目业绩总览表_-项目经理.xlsx` | 项目经理维度的项目组合总表 | 1 个 sheet（项目业绩汇总），含 YTD（年初至今）列 |

> 报表查询区间通常为 `2026-01 ~ 2026-07`（H1）。若区间变化，指标口径会随之变化，需在报告封面与叙述中同步。

## 二、部门表（1010）sheet 与导出映射

`extract.py` 按固定 sheet_id 导出，顺序与 ERP 导出一致，**不要改 sheet_id**：

| sheet_id | 内容 | 导出文件 |
|---|---|---|
| 000001 | 事业部业绩总表（预算 / 同比） | dept_budget.csv |
| 000002 | 关键指标（收入/毛利/利润/坏账/收款/开票… 月度+总计） | dept_keymetrics.csv |
| 000003 | 部门总表（按月的外部收入/项目收入/毛利/利润） | dept_total.csv |
| 000004 | 现金流量表（期末现金/未收款/应收账款） | dept_cashflow.csv |
| 000005 | 展开表 | dept_breakdown.csv |
| 000006 | 业绩绩效表（报告签回率等） | dept_perf.csv |

关键指标行名（dept_keymetrics.csv 第 3 行为表头，数据从第 4 行起）：
`外部收入 / 部门项目收入 / 部门毛利 / 毛利率 / 部门利润 / 部门利润率 / 人工成本 / 项目实施费用 / 销售费用 / 坏账准备 / 考核利润 / 考核利润率 / 开票金额 / 收款金额 / 部门净现金流 / 本期应提交报告阶段数 / 本期已提交报告阶段数 / 及时签回率`

> ⚠️ 成本类指标（坏账准备、人工成本等）在关键指标表里**带有负号前缀**（如 `-坏账准备`），`analyze.py` 的 `km_get` 已对「原值」与「-原值」两种写法兼容，解析为带符号数值，切勿再手工取负。

## 三、项目表（2010）列结构

- 表头有 3 行：第 1 行会计年度、第 2 行身份列名、第 3 行度量列名（YTD 列在每个度量组的**首次出现**处）。
- 列索引（0-based）：
  - `0` 项目编码
  - `1` 子项目名称
  - `2` 项目类型
  - `9` 子项目经理姓名
  - `13` 交付一级部门
  - **`14` 项目所属部门名称（★过滤用此列）**
  - `15` 项目经营部门名称（曾误用此列 → 见踩坑）
  - `17` 项目状态
  - YTD 度量列（索引 → 含义）：`37 业绩收入 / 38 人工成本 / 39 现场 / 40 外包 / 41 远程 / 42 项目费用 / 43 采购 / 44 项目毛利 / 45 毛利率 / 46 销售费用 / 47 管理费 / 48 项目净利 / 49 项目净利率 / 50 待定报告收入 / 51 坏账计提 / 52 无合同收入 / 53 累计开票金额 / 54 累计收款金额 / 55 已开票未收款 / 56 1年内应收 / 57 业绩现金流 / 58 工时`

### 项目过滤（最重要的一步）

- **过滤列 = `14` 项目所属部门名称**
- **过滤方式 = 精确全路径等于（`==`），不能模糊子串**
- 华北区数据治理部全路径：
  `Global事业部群.产业数智化.数智平台事业部.数据治理部.华北区`
- 该路径下共 **65 个项目**，其中 **28 个** 上半年有业绩收入（活跃口径：业绩收入>0）。

## 四、核心口径关系（写报告时务必核对）

| 指标 | 值 | 说明 |
|---|---|---|
| 外部收入 | 463 万 | 同比 +24.5% |
| 部门项目收入 | 316 万 | ≠ 项目业绩收入（口径差异） |
| 部门毛利 / 毛利率 | 87 万 / 27.4% | 同比 +8.5pp |
| 会计口径部门利润 | −13 万 | 被坏账拖累 |
| 考核利润 | 183 万 | 剔除坏账后为正 |
| 坏账准备 | 74 万 | 与项目坏账计提 74.0 万**完全吻合** |
| 项目业绩收入（65项目/28活跃） | 504.1 万 | 毛利前确认口径 |
| 项目毛利 / 净利率 | 171.4 万 / 26.0% | 毛利率 34.0% |
| 项目坏账 | 74.0 万 | 集中于「人力外包」类型 + 冉龙梅/刘伟 |
| 期末现金余额 | −161 万 | 现金为负的经营风险 |
| 已确认收入未收款 | 533 万 | 回款瓶颈 |
| 报告及时签回率 | 13.8% | 运营短板 |
| 年度签约目标 | 890 万 | 全年签约额目标（签约口径，非收入口径） |
| 上半年新签 | 171 万 | 新客户 / 新项目签约 |
| 上半年累计签约 | 327 万 | 含续签/老客户（新签 171 + 续签 156）；达成率 36.7%，下半年缺口 563 万 |

> **口径差异说明**：项目「业绩收入」(504.1万) > 部门「部门项目收入」(316万)，因前者是毛利前确认口径、后者是净收入口径（剔除部门间结算/内部/订阅等）。两者坏账数字一致，印证该子集即华北区交付基本盘。

## 五、踩坑清单（务必逐条规避）

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | `tencent-docs-sheetagent` skill 不可用 | 调该 skill 直接失败 | 改用本地 `editor_sdk`（`tencent-local-office-edit` 的 `edsdk.py`），`sheet_get_cell_data(return_csv=true)` 导出 CSV |
| 2 | `sheet_get_cell_data` 返回 JSON 包裹的 CSV | 直接当 CSV 读报错 | 先 `json.loads(stdout)["csv_data"]` 再 `csv.reader` |
| 3 | 项目未按区域过滤 | 误把全量项目当华北区，收入 623 万、坏账分散 | **必须按列14 精确全路径过滤**（见第三节），得 65/28 项目 |
| 4 | 误用「项目经营部门名称」(列15) + 模糊子串 | 混入其他区域数据 | 用列14「项目所属部门名称」+ 精确 `==` |
| 5 | 成本指标负号 | 坏账/人工成本被解析为 None 或符号错 | `km_get` 兼容 `-名` 写法，无需手工取负 |
| 6 | 活跃项目口径 | 用「毛利/净利>0」判活跃得 36 个，与已批报告 28 不一致 | **活跃 = 业绩收入>0**，与已交付报告口径对齐 |
| 7 | Python 中文引号 | `"出血点"` 用 ASCII 双引号截断字符串，SyntaxError | 用「」直角引号或全角 " " |
| 8 | editor_sdk 异步 open | 未 open 直接读 → "workbook is not open" | 先 `open_file` 再读；必要时 `sleep 2` 等就绪 |
| 9 | 坏账归因 | 仅看总额，不知来源 | 交叉「项目类型×经理×累计收款×应收」，定位到单一客户（计算机所）外包项目回款归零 |
| 10 | 报告签回率 13.8% | 易忽略为次要指标 | 这是运营核心短板，与回款/坏账同源（验收/确认卡顿） |
| 11 | 月度毛利率双重 ×100 | 图表里毛利率显示成 2000%~5000%+（如 55.77→5577%） | `analyze.py` 已把 `gp_rate` 存成小数(0.274)，生成端 `×100` 才正确；源不得再留百分比数值，否则二次放大 |
| 12 | `open_file` 参数名错 + 等待不足 | 项目表报 `workbook is not open`、CSV 为空、整链崩溃 | `open_file` 必须用 `file_path=`（不是 `file_id=`）；open 后 `sleep 4` 等异步就绪；每个文件只 open 一次 |
| 13 | 签约目标与收入口径混淆 | 把「年度签约目标 890 万」当收入，与「外部收入 463 万」放一起对比，读者误以为数据矛盾 | 签约额为合同签约口径、收入为确认收入口径，两者不在同一张表；报告第三章用独立表格呈现签约进度，不与收入指标混排 |
| 14 | 金额列是「带千分位逗号的文本」 | 直接 `float()` 抛异常被吞成 0，Backlog/收入全算成 0（如合同额 1620 万变 0） | 读项目业绩总览表时务必 `float(str(x).replace(",","").replace("%",""))`；`extract_backlog.py` 已内置，勿重复造轮子 |

## 六、输出文件

| 文件 | 内容 |
|---|---|
| `{区域}2026年上半年经营分析报告.html` | 含自绘 SVG 图表、KPI 卡片、核心汇报观点面板，可浏览器预览 |
| `{区域}2026年上半年经营分析报告.md` | Markdown 源 |
| `{区域}2026年上半年经营分析报告.docx` | 可编辑 Word（python-docx） |

报告章节（默认，13 章；用户追加章节时顺延）：封面 → **核心汇报观点**（前置）→ 一、执行摘要 → 二、经营概况与核心指标 → **三、目标达成与签约情况（上半年）** → 四、月度经营趋势 → 五、成本/费用/利润质量 → 六、项目业绩分析（经理维度）→ 七、现金流与回款 → 八、报告提交与签收 → 九、售前与业务拓展 → 十、团队与人员培养 → 十一、AI 创新应用 → 十二、问题诊断与改进建议 → **十三、合同储备与 Backlog 分析**。

> **三、目标达成与签约情况** 为可选章节：仅当 `metrics.json["signing"]` 存在时生成
> （`annual_target / signed_new / signed_total`，单位万元）。该章指标与正文「外部收入 463 万 /
> 部门项目收入 316 万」非同一口径——签约额为合同签约口径，收入为确认收入口径，报告中已用表格区分，避免混淆。

> **十三、合同储备与 Backlog 分析** 为可选章节：仅当 `metrics.json["backlog"]` 存在时生成
> （由 `scripts/extract_backlog.py` 读项目业绩总览表 xlsx 计算）。指标含：在手合同总额（税后）、
> 执行中/已关闭拆分、上半年已确认业绩收入(YTD)、**Backlog 未执行余额**（=执行中合同额−上半年已确认）、
> 待定报告收入(YTD)；并附**全量项目明细表**（按合同额降序，含合同额/上半年确认/累计确认/未执行余额）。
> Backlog 与签约额、收入均不同口径：签约额是合同额，Backlog 是合同额中尚未确认为收入的部分。
